# sprite_harmonize — 스프라이트를 장면 빛에 맞추기 (scene-relight)

2D 캐릭터 프레임의 색·명암·외곽선을 장면에 맞춘다. 한 번 맞추고(작은 JSON) 같은 장면·같은 빛의 모든 프레임에 적용한다.
알파는 그대로, 선화는 절대 밝아지지 않고, 그림자는 그리지 않는다.

- Claude Cowork 에서는 이 폴더가 그대로 스킬이다 → [`SKILL.md`](SKILL.md) (실행 순서, Adobe 단계, 검사 기준, 비용 규칙)
- 지금 상태와 버린 것 → [`HANDOFF.md`](HANDOFF.md) · 첫 단계(팩·워시·림)의 시도와 실패 → [`RESEARCH.md`](RESEARCH.md)
- 명령: [`relight.py`](relight.py) · 코드: [`scenelight/`](scenelight) · 테스트: [`tests/`](tests) (합성 그림만, 89개)

```bash
pip install -r requirements.txt
# A. 참고 팩: 중립 + 같은 포즈의 장면 빛 참고 -> 같은 방향 프레임
python relight.py fit neutral.png reference.png -o scenes/S.json --pack scenes/S.pack --sheet check.png
python relight.py apply scenes/S.json frames/*.png -o out/ --pack scenes/S.pack --view-from-name --sheet ba.png
# B. 장면 블렌드: 프레임 하나 + 화가가 장면 안에 그린 그 캐릭터 -> 모든 프레임 (게임 높이)
python relight.py blend-fit frames/idle.png scene.png -o blend.json --sheet check.png
python relight.py blend blend.json frames/*.png -o out/ --sheet ba.png
# C. 참고 룩: 원본 + 빛 받은 참고 한 쌍 (빛 종류마다 하나) -> 다른 프레임·동작
python relight.py look-fit orig.png lamp_ref.png -o look_lamp.json --sheet check.png
python relight.py look look_lamp.json frames/*.png -o out/ --sheet ba.png
```
B·C 는 그림 `X.png` 마다 Adobe 결과를 `masks/X/` 에 둔다: 부위 마스크 (`hair.png`, `skin.png`, `hands.png`, `shoes.png`,
`legs.png`, `tail.png`, C 는 옷 `upper.png`·`coat_vest.png` ..., 장면 그림에는 `subject.png`) + `image_vectorize` 선화 `vector.svg`.
받는 법 (어떤 호출을 어떤 파일 이름으로) 은 `SKILL.md`.
`preview` (배경 위 확인용 합성, 발밑 그림자는 미리보기 전용) 와 `check` 도 그대로 있다.

## 방법

| 방법 | 입력 | 하는 일 | 크기 | 검증 (자세히는 아래) |
|---|---|---|---|---|
| A. 참고 팩 (`fit`/`apply --pack`) | 중립 + 같은 포즈의 장면 빛 참고 | 참고를 중립에 화소 단위로 맞춰 두고, 관문(접힘 ≤ 0.055, 구조 일치 ≥ 0.68, 겹침 ≥ 0.71)을 넘은 같은 방향 프레임에 차이를 옮긴다. 가슴 구역은 선을 벽으로 쓴다. 못 넘으면 워시+림 | `transfer.py` `chest.py` `shading.py` | 린 숲 석양: 참고 일치 0.902, 색 오차 2.2 |
| B. 장면 블렌드 (`blend-fit`/`blend`) | 프레임 하나 + 화가의 장면 그림 + 두 그림의 Adobe 마스크 | 부위마다 L* 톤 곡선 + a*/b* 이동 (게임 크기에서 잼, 바깥 2 px 따로; 이름 없는 나머지는 `rest` 부위) → 머리 얼룩 정리 → premultiplied 축소 → 부위마다 장면 외곽선 색으로 ~1.3 px 바깥선 | `blend.py` 267줄 (v10 은 사례별 약 1600줄) | SKILL 마스크로 부위 L* 중앙값·a*·b* 화가와 1.6 이내 (손으로 묶은 검증 마스크 0.6) |
| C. 참고 룩 (`look-fit`/`look`) | 원본 + 빛 받은 참고 + 원본의 Adobe 마스크 | 실루엣 깊이 띠 × 빛 쪽 방향 칸마다 선형 RGB 로그 비 표 + 톤 기울기, ridge 최소제곱. 각 프레임 자신의 실루엣 기하로 적용, soft knee | `look.py` 약 290줄 | SKILL 마스크로 자기 dE 5.0~7.8 (그대로 두면 15~34), 새 흰 화소 0 |

공통: 부위·선은 Adobe 결과만 (`parts.py`). 알파 그대로 (B 는 원래 알파의 게임 높이 축소), Adobe 선화 화소는 밝아지지 않는다,
그림자 없음. A 는 Adobe 가 필요 없다.

## 숫자 뒤의 마스크
- **SKILL 마스크** = `SKILL.md` 의 Adobe 호출을 그대로 한 결과. B: P01 과 화가 그림에 2026-10-12 에 직접 다시 받았다 (hair, skin,
  hands, shoes, legs, tail, 장면에 subject; 옷은 `rest`). C: 같은 bodyParts + 옷 프롬프트 (린 P01: vest·belt → `coat_`,
  shirt·sleeves·tunic → `upper_`, 하의 → `lower`, gloves → `hands_`); 걷기·브루나·P02 는 이미 받아 둔 Adobe 결과를 같은 이름으로.
- **검증 마스크** = 연구 때 손으로 묶은 것 (설명용, 다시 만들지 않는다). B: 피부 = 얼굴·목·팔 ∪ (다리 − 신발), 옷 = 나머지,
  머리 빈 곳 보정, 화가 그림의 머리·얼굴·옷은 스프라이트 마스크를 옮겨 씀. C: 팔·얼굴 선택을 더 받고 묶음도 다르다.
- SKILL 마스크에서 옷 프롬프트를 빼면 (bodyParts 만) C 의 L1 자기 dE 가 8.54 로 검사(≤ 8)를 못 넘는다. 린 P01 의
  Upper Clothes / Coat 결과가 27 / 121 화소뿐이기 때문이다.

## B. 장면 블렌드 — 린 P01 ↔ 화가의 장면 그림 (게임 높이 1041, 같은 보드 위, 바닥 그림자 없이)

부위의 L* 중앙값 / 바깥 띠 L* (실루엣에서 1.5 px 안 화소의 중앙값), 두 블렌드 모두 검증 마스크의 부위 나눔으로 잰다.
v10 = 화가 맞춤형 긴 체인 (버림), 그냥 축소 = 지금 게임 그림.

| 부위 | 화가 | **SKILL 마스크** | 검증 마스크 | v10 | 그냥 축소 | | 화가 바깥 띠 | **SKILL 마스크** | 검증 마스크 | v10 | 그냥 축소 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 머리 | 74.2 | **73.9** | 73.7 | 73.9 | 83.4 | | 50.3 | **35.7** | 49.0 | 44.5 | 52.9 |
| 피부 | 79.7 | **78.7** | 79.2 | 79.4 | 86.9 | | 53.2 | **29.5** | 47.7 | 47.4 | 58.9 |
| 옷 | 33.9 | **35.5** | 33.4 | 33.8 | 42.3 | | 42.8 | **27.7** | 32.6 | 31.3 | 33.0 |
| 부츠 | 23.7 | **23.1** | 23.3 | 23.3 | 31.0 | | 14.3 | **19.1** | 15.3 | 16.1 | 22.4 |
| 꼬리 | 67.7 | **66.5** | 67.1 | 67.6 | 77.5 | | 30.2 | **31.8** | 29.6 | 39.3 | 40.6 |

- a*/b* 중앙값: SKILL 마스크 0.6 이내, 검증 마스크 0.6 이내 (예: 머리 11.2 / 17.0 vs 화가 11.4 / 16.9; 그냥 축소 6.2 / 6.4).
- SKILL 마스크에서 뒤지는 곳: 머리·피부·옷의 바깥 띠가 화가보다 어둡다 (35.7 / 29.5 / 27.7 vs 50.3 / 53.2 / 42.8) — 바깥선
  색을 화가 그림의 Adobe 마스크 가장자리에서 재기 때문이다. 시트 크기에서는 검증 마스크 결과와 거의 같아 보인다.
- 명령 출력 (`blend-fit`, SKILL 마스크): 검사하는 부위 (머리·신발·다리·꼬리·rest) 모두 장면과 L*·a*·b* 0.5 이내, 이름 붙은
  부위가 인물의 57 %, 알파 바이트 단위 동일, Adobe 선화 16848 화소 중 밝아진 것 0. 피부 (5084 게임 화소, 인물의 2.6 %) 는
  75.0 vs 78.4 — 가는 손목·얼굴이 이웃 곡선과 섞여서다 (참고용 줄).
- 검증 마스크에서도 남는 차이: 옷 바깥 띠가 화가보다 어둡다 (원래 외곽선 33.0 이 이미 어둡고 밝히지 않는 규칙이 지킨다; v10 도
  31.3). 곡선 하나가 어두운 조끼와 밝은 소매를 같이 다뤄 소매가 조금 회색이다.
- 시간 (1024×1536): 맞추기 약 3 초, 적용 2.6~4 초. 걷기 프레임 둘 (다른 옷, 맨발) 에 P01 에서 맞춘 것을 적용: 이름
  붙은 부위가 42 % / 37 % (신발 마스크 없음 → `rest` 곡선), 시트에서 멀쩡해 보인다.

## C. 참고 룩 — 한 쌍에서 맞추고 다른 프레임에 적용

L1 = 린 P01 달 + 랜턴, L2 = 린 P01 달빛, L3 = 브루나 램프 (빛 종류마다 참고 하나). walk a / b = 린의 다른 걷기 프레임, P02 = 다른 포즈 프레임.
v6 (계층 모델 + 띠 보정), v7 (화소별 GBM 모델) 은 이전 연구판이다 (버림, 저장소에 없음). **굵게 = look.py 가 뒤지는 곳.**
띠 지표는 각 열의 부위 나눔으로 잰다 (SKILL 열의 총수가 조금 다르다).

| 경우 | 지표 | look.py SKILL 마스크 | look.py 검증 마스크 | v6 | v7 |
|---|---|---|---|---|---|
| L1 자기 | 색 오차 dE (그대로 19.07) | **7.81** | 7.67 | 6.49 | 4.56 |
| L2 자기 | dE (그대로 33.54) | **5.98** | 5.78 | 5.29 | 3.55 |
| L3 자기 | dE (그대로 15.18) | **5.01** | 5.01 | 4.11 | 3.03 |
| L1 / L2 / L3 자기 | 부위 띠 실패 (dL*·db* > 2) | 13/50 · 5/47 · 0/42 | 12/54 · 5/52 · 0/42 | 14 · 10 · 0 | 23 · 11 · 0 |
| L1 walk a | 참고 변화와 3 이내인 띠 | 8/22 | 9/22 | 9 | 7 |
| L1 walk b | 〃 | **5/22** | 5/23 | 9 | 4 |
| L2 walk a | 〃 | **9/21** | 11/21 | 10 | 12 |
| L2 walk b | 〃 | **7/21** | 8/23 | 14 | 15 |
| P02 (L3) | 〃 | **21/28** | 21/28 | 28 | 28 |
| L1 walk a / b | 새 흰 화소 | 0 / 0 | 0 / 0 | 0 / 1 | 4258 / 4308 |
| L1 walk a / b | 빛 쪽 다리 dL* (먼 다리) | **+1.5 (+0.4) / +5.4 (+3.0)** | +1.5 (+0.4) / +5.3 (+3.0) | 2.7 (1.1) / 7.9 (5.3) | 7.0 (4.4) / 10.2 (6.5) |

- dE 는 `look-fit` 명령이 찍는 값이다 (SKILL 열). L1 7.81 은 검사선 8 에 가깝다; bodyParts 만이면 8.54 로 못 넘는다.
- 빛 방향은 쌍에서 잰다 (L1 152°, L2 30°, L3 147°; 0 = 화면 오른쪽, 90 = 위). 발이 바뀌면 밝은 다리도 바뀐다 (모든 경우).
- 모든 결과: 알파 동일, 투명 화소 그대로, Adobe 선화 화소 0개 밝아짐 (어느 채널도), 참고가 원본의 90~94 % 와 겹친다.
  깊은 안쪽의 신뢰도 끊김(이음매) 0 (고치기 전 P02 539). 맞추기 약 5 초 (확인 포함), 적용 2.5~4 초.
- 남는 차이: 자기 dE 와 일부 전달이 v6/v7 보다 나쁘다 (작은 매끈한 모델, 머리카락 한 올 단위 없음). 가는 다리 가운데
  희미한 줄 (2배 확대에서만), 달빛에서 올리브 천이 청록, 밝은 재질은 참고만큼 밝아지지 않고 주황으로 남는다.
- C 에 `rest` 부위를 넣어 보았다: 자기 dE 는 조금 좋아졌지만 (L1 7.79) 린의 부위 띠와 걷기 전달이 나빠져서 넣지 않았다.
- look.py 를 고른 이유: 작고(약 290줄) 화소별 학습 모델이 없고, 새 흰 화소·이음매가 없고, 선화를 지키고, 실루엣 기하만으로 다른
  동작에 옮겨진다. 차이를 줄이는 연구는 더 하지 않는다 (`SKILL.md` 비용 규칙).

## A. 참고 팩 — 린 숲 석양 (중립 1024×1536 ↔ 따뜻한 참고)

이름표 없는 격자 지표 (`fit` 출력): 참고와의 명암 모양 일치 (1 = 같음), 저주파 색 오차, 원화 모양 보존 (가슴 가운데 작은 명암, 1 = 그대로).

| 방법 | 참고 일치 | 색 오차 | 원화 모양 보존 | 평균 L* (참고 66.0) |
|---|---|---|---|---|
| 중립 (지금 게임 그림) | 0.476 | — | 1.000 | 79.9 |
| 워시 + 림 (팩이 없거나 관문을 못 넘을 때) | 0.668 | 6.8 | 0.995 | 66.0 |
| **참고 팩 + 가슴 단계** | **0.902** | **2.2** | 0.953 (몸 전체 전달) | 66.3 |

다른 옷 턴어라운드 8방향·좌우반전·잘린 그림은 관문을 못 넘어 워시+림이 된다 (안전한 쪽). 가슴 단계가 들어간 최종 결과의 모양
보존 값은 0.832 — 가슴 안쪽이 일부러 참고의 빛을 따르기 때문이다. 팩에는 사용자 그림이 들어 있다 → 공개 저장소 금지 (`.gitignore`).

## 한계
- 특별한 경우 (다른 옷·방향, 잘린 그림, 마스크가 안 맞는 프레임) 는 도구로 풀지 않는다: 그 프레임의 빛 받은 그림을 주문해서
  Adobe `image_remove_background` 로 오려 쓴다.
- 그림자 (바닥·발밑) 는 만들지 않는다 — 게임 엔진의 몫이다.
- 픽셀아트용이 아니다. 렌더된 최종 프레임에 쓴다 (원화 파츠에는 쓰지 않는다).
