# CLAUDE.md — lyn-sprites (카프카의 굴 2D 게임, 캐릭터 Lyn 걷기 스프라이트 파이프라인)

이 저장소는 **AI 가 그린 걷기 시트(원화)를 받아 → 프레임 은행 → 자세·위상 → 짝 → 8프레임 루프 조립 → Godot 리소스**
로 만드는 파이프라인이다. 연구는 끝났고(`docs/research/`), 여기서는 그 결론을 **재현 가능한 코드**로 만든다.

## 응답 규칙 (사용자 지시)
- 모든 작업 응답 첫 줄에 필요 노력을 적는다: `필요 노력: 낮음 | 중간 | 높음 | 엑스트라 | 최대`.
- "됐다"고 말로만 하지 말고 결과 이미지(스트립·GIF)와 수치를 보여준다.
- 실패한 시도는 지우지 말고 `docs/research/failures.md` 에 사실대로 적는다.

## 절대 규칙 (연구에서 확정된 것 — 다시 시도하지 말 것)
1. **색칠·재채색 금지.** 옷은 원화 화소를 그대로 가져온다.
2. **옷을 행(row) 단위로 늘리거나 잘라 붙이지 않는다** (row-warp 는 24% 화소 중복·찢김을 만들었다). 파츠는 통째로 옮긴다.
3. **팔을 색·성분으로 분리하려 하지 않는다.** 이 옷은 장갑·조끼·파우치·레깅스가 같은 갈색(≈90,60,45)이고 셔츠 무늬가 살색이다.
   대신 절단선을 **팔꿈치 위 t=0.42** 에 두어 어떤 팔다리도 두 프레임에 걸쳐 잘리지 않게 한다.
4. **프레임 번호로 세트를 비교하지 않는다.** 자세(발·손·팔·다리 벌어짐)로 맞춘다. 순서는 검증(lag-1 상관)하고 쓴다.
5. **캐논 = 색감·크기·비율** 이지 위치가 아니다. 캐논 1장을 그대로 복사해 걷게 만들지 않는다.
6. **뷰 간 전이 금지**(측면↔정면). 반전은 같은 뷰 안에서만 (측면 서→동, 정면 좌우반전 = 위상 +0.5).
7. 모르는 화소(가려진 부분, 꼬리·망토 겹침)는 모른다고 남긴다. 추정으로 채우지 않는다.
8. Godot 쪽 기존 동작(Background, Dig, Room, Light, Walk)은 바꾸지 않는다.

## 좌표 규약 (모든 모듈이 공유)
- 정규화 캔버스 **640×720**, 몸(꼬리 제외) 높이 **H=600**, **머리 중심 x=330, 발바닥 y=680**. 균일 스케일(키·너비 같은 비율).
- 몸축 **t** = (y − 정수리)/H, 0=정수리 1=발끝. 절단선·띠는 전부 t 로 말한다 (허리 띠 t .40~.44, 손 띠 .46~.62, 발 띠 >.88).
- 측면은 전부 **동쪽(오른쪽 보기)** 로 통일. 방향 판정 = 꼬리 위치(밝은 털, 허리 아래, 중심에서 0.12H 밖)의 반대.
- 위상 **phi ∈ [0,1)** = 한 보행 주기(두 걸음). 측면: phi 0 = 가까운 다리가 앞·보폭 최대, 0.5 = 먼 다리가 앞.
  정면: phi 0 = 화면 오른발(해부학적 왼발) 최대 앞.

## 확정된 측정 사실 (골든 파일 `golden/` 과 일치해야 한다)
- 측면 N/F(가까운 다리가 앞인가) = **앞다리−뒷다리 밝기**. AI 는 먼 다리를 어둡게 칠한다 (나체 피부 −2 vs +33, 착의 레깅스 −3 vs +5).
  봉우리 run 단위로 라벨하고 N/F 교대를 강제한다.
- 정면 앞발 = **더 넓은 발**(발끝 y 차는 1px 수준이라 못 쓴다). 정면 원화는 사각파 걸음(6장 벌림 → 1~2장에 교대).
- 착의 정면 원화는 앞발 쪽으로 꼬리가 바뀐다; 나체 캐논은 항상 오른쪽 → 꼬리는 **고정 레이어**.
- 두 AI 레퍼런스는 걸음 진폭·배치·비율이 다르다(측면 보폭 1.13~1.28배, lean, 머리 폭). 선택으로는 못 고친다.
- 상의(t<0.4)는 걸어도 실루엣이 안 변한다(sd 2px). 장화·레깅스는 다리를 따라간다.

## 파이프라인 (platekit/walkbank/, 실행 순서)
```
bank.py       시트 → frames/{set}_{i:02d}.png, norm/ (정규화), labels.json
posebank.py   측면 자세·N/F·theta·phi → pose.json
pairs8.py     착의↔나체 8위상 짝 + 다리/팔 기증 후보 → pairs8.json
assemble.py   측면 8프레임: A 고정 상부+기증 하부 (권장), B 상하체 분리, C 머리 잠금
frontwalk.py  정면: 자세(fw,dy,손)·idle 제외·반전 증강·목표 fw 선택·고정 꼬리·조립
```
현재 경로가 하드코딩되어 있다(`/root/.claude/uploads/...`, `/home/claude/handoff/work/bank`). **첫 작업은 이것을
CLI 인자/설정으로 바꾸는 것**이다 (`platekit walkbank build --sheets assets/raw/sheets --out build/`).

## 개발 방식
- 모듈을 옮길 때 동작을 바꾸지 않는다. `golden/*.json` 과 같은 결과가 나와야 한다 (labels 437장, pose 293장, pairs 8쌍, front pairs 8쌍).
- 테스트 우선: `tests/` 에 합성 시트(작은 격자)와 합성 신호로 단위 테스트, 골든 파일로 회귀 테스트. `pytest -q` 가 CI 다.
- 큰 이진 파일(시트 PNG, 은행)은 git 에 직접 넣지 않는다 — 시트는 Git LFS, 은행(`build/`)은 재생성 산출물로 .gitignore.
- 한 PR = 한 마일스톤(아래). 계획 모드로 설계 → 승인 → 구현 → 스트립/GIF 첨부.

## 마일스톤
- M1 `bank` CLI 화 + 테스트 (격자 슬라이스, 방향 판정, 정규화 좌표)
- M2 `pose` 측면/정면 자세·위상 + 골든 회귀

- M4 `assemble` 측면 A / 정면 A → `build/walk/{dir}/{i}.png` + 미리보기 GIF
- M5 `export` Godot 4.3+ SpriteFrames(.tres) + 아틀라스, 기존 walk compiler(5방향→8방향) 와 연결
- M6 북쪽·대각 시트 추가 시 같은 파이프라인 (뷰별 자세 신호만 교체)
