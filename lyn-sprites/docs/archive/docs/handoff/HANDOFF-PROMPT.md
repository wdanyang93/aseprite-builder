## 0. 한 문장 요약

**원화의 디자인·색·명암·체형은 정본이지만 팔·다리의 위치와 위상은 틀렸다.
일반 걷기 규칙을 먼저 세우고, 그 규칙에 맞는 외곽을 결정한 뒤, 색과 명암은
원화에서 추출해 채우는 도구를 만들고 있다.**

## 1. 절대 지켜야 할 원칙 (반복해서 어긴 것들)

### 1-1. 원화는 포즈의 정본이 아니다

가장 많이 반복한 실수다. 검출이 실패하면 알고리즘을 의심하고, 원화가 이상하면
"원화가 그렇게 그려져 있다"고 넘어갔다. **둘 다 틀렸다.**

```
정본인 것      디자인, 색, 명암 팔레트, 체형, 등신, 선 스타일
정본이 아닌 것  팔·다리 위치, 프레임 간 연속성, 좌우 교차, 어깨 위치
```

원화 8프레임은 AI가 대충 만든 것이어서 **팔 따로 다리 따로 다음 동작 따로**다.
이것을 일반 걷기로 고치는 것이 이 도구의 존재 이유다.

### 1-2. 두 프레임으로 사이클을 정의하지 마라

f1과 f2만 보고 그 사이를 보간하면 f3부터 다시 엉망이 된다. 실제로 그렇게 했다가
지적받았다. **8프레임 전체를 하나의 사이클로 계획**해야 한다.

### 1-3. 새로 그리지 않는다

생성형 재그림·확산 모델·외부 이미지 API 금지. 기존 픽셀을 **잘라서 옮기고 변형**한다.
AI가 새로 그린 팔(JPG로 온 것)은 자세가 달라 쓸 수 없었다.

### 1-4. 파일 크기를 바꾸지 마라

사용자가 편집한 판을 받을 때 **프레임 원본 크기 그대로**여야 한다.
격자 이미지를 편집해 받는 방식은 역산 오차가 커서 실패했다(IoU 36%).
프레임 크기로 직접 작업한 판은 역산 없이 바로 썼다(IoU 91~99%).

### 1-5. 결과를 파일로 제시하라

사용자는 내 화면을 볼 수 없다. 작업이 끝나면 **번호 붙인 검수 이미지를 항상 첨부**한다.
좌표 지정이 필요하면 격자(굵은 선 20px, 얇은 선 4px)를 함께 준다.

## 3. 측정으로 확정된 사실 (추측하지 말고 이 값을 쓰라)

### 3-1. 고정점 — 레퍼런스 8프레임 실측 (신장 정규화)

```

어깨    y 0.170   sd 0.0076   거의 고정  <- 회전 고정점으로 쓴다

**어깨는 핀이다.** 팔을 어깨 기준으로 회전시킬 수 있지만 어깨를 옮겨선 안 된다.

### 3-2. 등신 차이 — 신장 비율은 전이되지 않는다

```

47시그마 차이인데 이건 오류가 아니라 비율이다. **레퍼런스에서는 허용 오차만 가져오고,
위치는 캐릭터 자신의 8프레임 중앙값과 비교**한다.

**권장: f5를 주 복구원, f3로 색 보정.** 남는 1%(약 50px)는 인페인팅 금지, 미복구 표시.

## 7. 사용자와 협업하는 방식

### 7-1. 좌표 지정

격자 이미지를 드린다. **굵은 선 + 숫자 20px, 얇은 선 4px.** 배율은 8~11배.
좌표는 `(142,186) -> (134,200) -> (130,220)` 형식으로 받는다.

### 7-2. 손작업 판 받기

**프레임 원본 크기 그대로** 요청한다. 축소하면 역산이 실패한다.
알파 PNG로 받되, 알파 저장이 안 되면 **형광색(마젠타/초록)으로 칠하도록** 요청한다.
흰색으로 칠하면 캐릭터의 흰 옷과 구분되지 않는다.

### 7-3. 손작업 판을 정답으로 활용

받은 판을 정합해 IoU를 재고, 내 규칙이 어디서 틀렸는지 역산한다.
이 방식으로 IoU 65.7% -> 99.3% 까지 올린 사례가 있다.
사용자 라벨은 **회귀 픽스처**로 박아 둔다 (cells.py 의 LABELLED_FRAME_1 참고).

### 7-4. 검수 이미지 형식

```
왼쪽 원본 | 오른쪽 판정 결과   (부위별 색상)
색상 규약: 파랑=몸통 빨강=머리 노랑=귀 보라=꼬리
          밝은녹색=near다리 진한녹색=far다리
          밝은주황=near팔 진한주황=far팔
          자홍=미복구/오류
프레임 번호를 크게, 측정값을 작게 병기
```
